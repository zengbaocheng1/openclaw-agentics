# Knowledge Formatting Reference

This reference provides best practices for formatting extracted knowledge.

## Summary Guidelines

- Keep summaries to 1-3 sentences
- Answer: What is this about? Why does it matter?
- Use the original language of the content

## Tagging Conventions

Use lowercase, hyphen-separated tags:

| Category | Example Tags |
|----------|-------------|
| Domain | `tech`, `finance`, `health`, `cooking`, `travel` |
| Type | `tutorial`, `news`, `reference`, `opinion`, `how-to` |
| Language | `cn`, `en`, `jp` |
| Tool/Platform | `python`, `linux`, `docker`, `react` |

## Content Types and Formatting

### Technical Tutorials

- List prerequisites
- Numbered steps for procedures
- Include code blocks with language tags
- Note common pitfalls

### News Articles

- Who, What, When, Where, Why
- Key statistics or data points
- Context/background if relevant

### Reference Material

- Organize by topic/subtopic
- Use tables for comparisons
- Include source links for follow-up

### Opinion/Essays

- Main argument/thesis
- Supporting points
- Counter-arguments mentioned
- Author's conclusion

## Memory Integration

When saving knowledge, consider whether it should also update:

1. **MEMORY.md**: For long-term important knowledge (personal context, recurring topics)
2. **TOOLS.md**: For tool/configuration related knowledge
3. **HEARTBEAT.md**: For reminder-style knowledge (things to check periodically)
